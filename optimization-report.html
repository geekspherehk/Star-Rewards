项目概览

技术栈：Vanilla JS + HTML + CSS（前端） / PHP + MySQL（后端，Hostinger 部署）/ Capacitor（移动端封装）

核心功能：用户注册/登录（JWT）、行为积分记录、愿望清单管理、积分兑换、成长日记、多主题切换、中英双语

架构特征：无构建工具、无框架、无模块系统，全靠全局函数 + <script> 标签串联，Service Worker 做 PWA 离线缓存

核心结论：项目功能完整、后端安全意识良好（PDO 预处理、JWT、bcrypt），但前端存在明显的架构债务（大量重复代码、Supabase 遗留）、安全漏洞（XSS）、性能瓶颈（全量刷新）和体验短板（无删除/编辑/加载态）。建议分三个阶段迭代优化。

1. 安全问题
1.1 成长日记 XSS 漏洞 Critical

script.js 第 1192 行，updateDiaryList() 使用 innerHTML 拼接 HTML 时，behavior.description 和 gift.name 未经过 escapeHtml() 处理直接插入。攻击者可通过注册账号输入恶意脚本（如 <img src=x onerror=alert(1)>），在其他用户查看日记时执行任意 JS。

修复：在拼接 HTML 前对所有用户输入字段调用 escapeHtml()，或改用 textContent + DOM API 构建元素。
1.2 textToHtmlWithLinks 函数 URL 注入风险 Critical

script.js 第 629-661 行，该函数将用户输入的文本转为带链接的 HTML，虽然做了协议白名单检查，但 URL 中的特殊字符（如 "）未转义，可闭合 href 属性注入 onclick 等事件处理器。该 HTML 通过 innerHTML 写入页面。

修复：在构建 <a href="..."> 之前，对 URL 做 escapeHtml() 处理，确保双引号被转义为 &quot;。
1.3 CORS 配置允许通配符 High

api/index.php 第 16-17 行，当请求不带 Origin 头时，Access-Control-Allow-Origin: * 被设置。某些工具或非浏览器客户端可不携带 Origin 头访问 API。

修复：移除通配符 fallback，严格限定 ALLOWED_ORIGIN，无 Origin 时返回 403。
1.4 无 API 速率限制 High

register 和 login 接口无任何速率限制，可被暴力破解密码或批量注册。后端虽用了 bcrypt（cost=12），但无登录失败锁定 / IP 限频。

修复：在 PHP 层加入基于 IP + email 的速率限制（如 5 次/分钟），或使用 Hostinger 的 .htaccess 限频模块。
1.5 JWT Token 存储在 localStorage Medium

Token 存储在 localStorage 中，任何 XSS 漏洞都可直接窃取用户令牌。结合上述 XSS 漏洞，风险被放大。

修复：优先修复 XSS 漏洞。若条件允许，改为 HttpOnly Cookie + CSRF Token 方案。
1.6 无 Token 吊销机制 Medium

JWT 是无状态的，logout 接口仅验证 token 有效性但不做任何服务端吊销。Token 在过期前（24小时）始终有效，即使用户已登出。

修复：增加 token_blacklist 表，logout 时将 token 的 jti 写入黑名单，verifyToken 时检查。
2. 架构问题
2.1 三套主题完全独立，约 3,300 行重复代码 Critical

theme_juanwa.html + script_juanwa.js + style_juanwa.css（约 1,870 行）
theme_juanziji.html + script_juanziji.js + style_juanziji.css（约 1,736 行）
与 index.html + script.js + style.css 功能几乎完全一致，仅文案和配色不同。任何 bug 修复或功能新增需要改三处。

修复：合并为单一入口，通过 CSS 变量 + i18n 切换主题。后端 user_configs.selected_theme 已支持，前端只需读取后动态加载样式。
2.2 Supabase 遗留代码遍布全项目 High

项目已从 Supabase 迁移到自建 PHP+MySQL API，但遗留大量死代码：
- supabase.min.js 仍在项目根目录（未被使用）
- sw.js 缓存列表包含 supabase.min.js
- script.js 第 68-81 行 initializeSupabase() 返回 null
- login.js supabase 变量声明
- localStorage 中存 supabase.user、supabase_session 等废弃 key

修复：删除 supabase.min.js，清理所有 supabase 引用和 localStorage key，更新 SW 缓存列表。
2.3 updateAuthUI 函数重复定义 High

script.js 中 updateAuthUI 被定义了两次（第 145 行和第 851 行），第二个定义覆盖第一个。第一个版本引用 showLoggedInState/showNotLoggedInState，第二个版本引用 logged-in 元素（HTML 中不存在）。实际行为不可预测。

修复：删除第 851 行的重复定义，保留第 145 行版本并确保与 HTML 结构匹配。
2.4 showTemporaryMessage / escapeHtml 在多处重复定义 Medium

showTemporaryMessage 在 script.js 和 login.js 各有一份，实现不同（一个用 inline style，一个用 class）。escapeHtml 同样在两文件各定义一次，且正则不同。

修复：提取到 utils.js 公共文件，所有页面统一引用。
2.5 无模块系统 / 无构建工具 Medium

所有 JS 通过 <script> 标签全局加载，函数全部挂在 window 上。无 ES modules、无 bundler、无 tree-shaking、无 minification。文件版本管理靠 ?v=2 query string 手动维护。

修复：引入 Vite 或类似轻量构建工具，使用 ES modules，自动处理 minify / cache busting / tree-shaking。
3. 性能问题
3.1 每次操作都全量拉取数据 High

addPoints()、addGift()、redeemGift() 每次操作后都调用 loadDataFromCloud()，该函数并发请求 4 个 API（profile + behaviors + gifts + redeemedGifts）。添加一条积分记录后，重新拉取所有历史数据，浪费带宽和渲染时间。

修复：操作成功后做增量更新 - 本地 push 新记录 + 更新积分显示，不再全量 reload。仅在页面加载时全量拉取。
3.2 Google Fonts @import 阻塞渲染 Medium

style.css 第 2 行使用 @import url('https://fonts.googleapis.com/...')，这是渲染阻塞请求，且依赖第三方 CDN。在网络不佳时页面文字会延迟显示。

修复：改为 <link rel="preload"> + <link rel="stylesheet"> 放到 <head>，或使用 font-display: swap。
3.3 日记列表用字符串拼接 + innerHTML Medium

updateDiaryList()（第 1139-1252 行）在循环中用 html += 拼接大量 HTML 字符串，然后一次性 innerHTML。当行为记录较多时（500 条上限），字符串拼接 + 解析 HTML 开销大。

修复：改用 DocumentFragment + createElement 构建 DOM，或使用虚拟列表只渲染可见区域。
3.4 生产环境大量 console.log Low

script.js 有 30+ 处 console.log，login.js 有 10+ 处。这些日志在生产环境暴露内部逻辑和用户邮箱信息。

修复：引入 loglevel 库或在构建时通过 Terser 的 drop_console 移除。
3.5 Service Worker 缓存列表过时 Low

sw.js 缓存 supabase.min.js（已废弃），但不缓存 i18n.js、login.js、api/api-client.js、i18n.css。缓存版本号 star-rewards-v1 从未更新，部署新代码后用户拿到的是旧缓存。

修复：更新缓存列表，每次部署时递增版本号，或改用 Workbox 的预缓存策略。
3.6 Service Worker 未注册 Medium

sw.js 存在但在 index.html 和 login.html 中没有 navigator.serviceWorker.register() 调用，PWA 离线功能实际未启用。pwa-manager.js 虽有注册逻辑，但未被任何页面引用。

修复：在页面中引入 pwa-manager.js 并确认注册逻辑执行。
4. 代码质量
4.1 i18n 不完整，大量硬编码中文 High

虽然有 i18n.js 翻译系统，但 script.js 中大量消息仍是硬编码中文：
- 第 619 行：`成功添加 ${change} 分！`
- login.js 中：'请输入邮箱和密码'、'注册成功！请登录'
- 第 1165 行：date.toLocaleDateString('zh-CN') 硬编码 locale
英文用户会看到中英混杂的界面。

修复：将所有硬编码文案迁移到 i18n 翻译表，日期格式化使用 currentLanguage 决定 locale。
4.2 i18n.js 中重复的 key Medium

i18n.js 中 behaviors 对象的 addBehavior key 被定义了两次，后者覆盖前者。zh 和 en 都有此问题。

修复：合并为单一 key，删除重复定义。
4.3 index.html 大量内联样式 Medium

index.html 第 39-52 行的认证状态卡片使用大量 inline style（background: linear-gradient(...)、padding、border-radius 等），既不便于维护，也无法利用 CSS 缓存。

修复：提取到 style.css 中使用 class 选择器。
4.4 死代码 / 空函数 Medium

- saveDataToCloud()（第 1083-1086 行）：函数体只有 console.log，不做任何事
- initializeSupabase()：返回 null
- validatePointsInput / validateGiftPointsInput：定义了但从未调用
- loadDataFromSessionStorage：在已登录场景下不会被调用
- api.resendConfirmation：直接返回假数据，不调用后端

修复：逐一删除或标记 @deprecated，确认无引用后清除。
4.5 updateDiaryList 大量内联样式 Medium

updateDiaryList() 函数在拼接 HTML 时使用了大量内联样式（如 style="margin-bottom: 8px; padding: 8px; background: #f8fff8; border-left: 3px solid #4CAF50; border-radius: 4px;"），难以维护和主题化。

修复：提取为 CSS class（如 .diary-item--positive、.diary-item--negative），主题切换时只需改 CSS 变量。
4.6 魔法数字遍布代码 Low

代码中大量硬编码数字：积分上限 10000、商品描述截取长度、500 条行为记录上限等，散布在各函数中，无常量定义。

修复：在文件顶部定义 const MAX_POINTS = 10000 等常量，统一引用。
4.7 无统一错误处理策略 Medium

各 async 函数的 catch 块处理方式不一致：有的 console.error + showTemporaryMessage，有的只 console.error，有的直接 throw。用户看到的错误信息格式不统一。

修复：创建 handleError(error, context) 统一函数，集中处理日志 + 用户提示 + 错误上报。
5. 数据库设计
5.1 behaviors 表无软删除 / 编辑支持 High

数据库只有 INSERT 操作，前端无删除 / 编辑行为记录的功能。用户误操作添加错误积分后无法修正，只能通过兑换礼物来"消耗"错误积分。

修复：增加 is_deleted TINYINT DEFAULT 0 字段支持软删除，API 增加 deleteBehavior action，前端增加删除按钮。
5.2 gifts 表无编辑 / 删除支持 High

礼物只能添加和兑换，不能编辑或删除。用户添加了错误的礼物名称 / 积分后无法修改。

修复：API 增加 updateGift / deleteGift action，前端增加编辑和删除入口。
5.3 redeemed_gifts 表缺少 gift_id 外键约束 Medium

redeemed_gifts.gift_id 字段存在但无外键约束（可为 NULL），兑换记录与原礼物之间无引用完整性保证。如果原礼物被（未来）删除，兑换记录中的 gift_id 会变成悬挂引用。

修复：当前设计（兑换时复制 name/points 到 redeemed_gifts）是合理的反范式冗余，但应加注释说明设计意图，或在 gift_id 上加 SET NULL 外键。
5.4 无分页支持 Medium

getBehaviors 和 getGifts 一次返回全部记录（无 LIMIT / OFFSET）。虽然目前有 500 条前端限制，但长期使用后数据量增长会导致响应变大、渲染变慢。

修复：API 增加 page / pageSize 参数，前端实现"加载更多"或无限滚动。
5.5 无数据库索引优化 Low

当前索引基本合理（idx_behaviors_user_time, idx_gifts_user_created, idx_redeemed_user_date），但 profiles 表无 user_id 之外的索引。随着用户增长，getProfile 查询仍可接受，但批量统计（如全站积分排行）将变慢。

修复：当前规模下可接受。未来如增加排行榜功能，需添加 total_points 索引。
6. UX 与功能缺失
6.1 无加载状态 / Skeleton Screen High

数据加载期间页面无任何加载指示器（spinner / skeleton / progress bar）。用户点击"成长日记"等模块时，如果网络慢，页面表现为空白，用户不知道是在加载还是出错了。

修复：在数据请求前显示 skeleton / spinner，请求完成（成功或失败）后隐藏。使用 loading 状态变量控制。
6.2 无操作确认 / 撤销机制 High

兑换礼物、添加积分等操作无二次确认。用户误点"兑换"按钮会直接扣除积分，且无法撤销（数据库无软删除）。

修复：关键操作（兑换礼物、大额扣分）增加确认对话框。理想情况下支持"撤销"（5 秒内可回退）。
6.3 无离线数据同步 Medium

Service Worker 的 syncData() 是空函数（只有 console.log），sync 事件监听器存在但无实际同步逻辑。用户离线时无法添加积分 / 礼物，网络恢复后也不会自动同步。

修复：使用 IndexedDB 存储离线操作队列，Service Worker 的 sync 事件触发时批量提交。或使用 Workbox 的 Background Sync API。
6.4 无密码重置功能 Medium

用户忘记密码后无法自助重置。后端 api/index.php 无 resetPassword / forgotPassword action，前端无相关入口。

修复：增加密码重置流程：邮箱验证 -> 生成临时 token -> 重置页面 -> 更新密码。
6.5 无数据导出功能 Low

用户无法导出自己的行为记录、积分历史、兑换记录。对于家长来说，可能需要打印或备份这些数据。

修复：增加"导出为 CSV / PDF"功能，后端增加 exportData action。
6.6 移动端手势支持不足 Low

虽然有 mobile-app.js 和 Capacitor 封装，但核心交互（切换模块、删除记录）依赖点击，无滑动手势。儿童使用时，滑动删除比点击更自然。

修复：引入轻量手势库（如 Hammer.js）或自行实现 touch 事件，支持左滑删除、左右切页。
6.7 无家长 / 儿童角色区分 Medium

作为"儿童行为激励管理"应用，当前所有用户权限相同。儿童可以自行添加积分、兑换礼物，没有家长审核 / 审批机制。

修复：增加 role 字段（parent / child），家长账号可管理儿童账号、审核积分变更和兑换请求。

后端安全亮点（值得保持）
PHP 后端安全实践良好 Good

后端代码体现了较好的安全意识，以下实践应继续保持：

- PDO 预处理语句防 SQL 注入（ATTR_EMULATE_PREPARES => false）
- bcrypt 哈希存储密码（cost=12）
- JWT 使用 HMAC-SHA256 签名 + hash_equals 防时序攻击
- 密码长度验证（6-255）
- 邮箱格式验证（filter_var）
- 安全响应头（X-Content-Type-Options, X-Frame-Options, Referrer-Policy）
- 数据库 CHECK 约束（积分非负、礼物积分必须 > 0）
- 外键级联删除（ON DELETE CASCADE）
- 预编译 SQL 中参数化查询，无字符串拼接
