技术方案最终修订（采纳架构师意见）

  1. 授权收敛：只给 profiles 加 family_id（behaviors/gifts/redeemed 不加），统一在 resolveProfileId 入口校验"档案属当前家庭"；users.family_id 不加，family_members 为唯一事实源。
  2. 建家庭惰性化：注册不自动建家庭；createFamily 首次创建；老用户由一次性迁移脚本建家庭。迁移前先导出线上 schema 核对（仓库 mysql.sql 已过期），全量备份，ADD COLUMN 带 DEFAULT，全部 id 用 BIGINT。
  3. 权限：JWT 不加 family/role（24h token 会过期失效）；写操作统一走 requireMember，管理操作走 requireOwner，每请求查 family_members（static 缓存）。
  4. 并发：现有原子自增 + FOR UPDATE 正确；补 rowCount 校验（read-after-delete）；负分应用层兜底（非严格模式 CHECK 不生效）。
  5. 邀请码：6–8 位免混淆字母数字（去 0/O/1/I）+ UNIQUE + joinFamily 双重限流（IP + 按码）。

五、R1 工程交付包

5.1 家庭共享（Family Sharing）—— 本迭代主交付

背景与目标：产品定位"家长共同参与记录"，但当前一个家庭只有主账号能记录。目标：家人（配偶/老人）可通过邀请加入同一家庭，共同为孩子的档案记录积分、兑换愿望，且各自独立登录、看到同一份家庭数据。

5.1.1 用户故事

US-01 作为家庭创建者（Owner），我可以在设置页创建家庭、生成 6–8 位邀请码，使家人能加入。Acceptance：邀请码 24h 有效；Owner 可撤销并重新生成。
US-02 作为家人（Member），我可以用邀请码加入家庭，之后登录即看到家庭全部孩子档案并记录。Acceptance：加入后默认选中家庭第一个孩子；无需重新建档案。
US-03 作为任意家庭成员，我都可以记录行为、添加愿望、兑换、查看日历/成就（共同参与模型，不做审核）。Acceptance：所有写操作对家庭成员生效并实时可见（刷新/切页后一致）。
US-04 作为成员，我可以在设置页查看家庭与成员列表、退出家庭；Owner 可以移除成员。Acceptance：移除后该成员失去访问权；被移除成员的数据不删除（档案归家庭）。
US-05 作为既有用户（已有档案），升级后我的档案自动归属我创建的家庭，历史数据不丢。Acceptance：迁移后行为/兑换/成就数据完整。

5.1.2 技术方案要点

  • 数据模型：新增 families（id, name, invite_code, invite_expires_at, created_at）；family_members（id, family_id, user_id, role: owner/member, joined_at，UNIQUE(family_id,user_id)，唯一事实源）；profiles 加 family_id（与 user_id 并列，统一在 resolveProfileId 校验"档案属当前家庭"）；behaviors / redeemed_gifts 加 added_by（记录归属：谁记的）。不建 users.family_id。
  • 兼容迁移：老用户由一次性迁移脚本建家庭（Owner），profiles 挂到家庭；新用户注册不自动建家庭，createFamily 首次惰性创建。迁移前先导出线上 schema 核对（仓库 mysql.sql 已过期）、全量备份、ADD COLUMN 带 DEFAULT、id 用 BIGINT；脚本可回滚。老 API 调用继续可用（family_id 默认取该用户所属家庭，经 family_members 查询）。
  • API（新增 action）： 
    createFamily(name)            → family + invite_code
getFamily()                   → 家庭信息 + 成员列表 + 档案
inviteMember()                → 生成/刷新邀请码（Owner）
joinFamily(code)              → 加入家庭（Member）
removeMember(user_id)         → Owner 移除成员
leaveFamily()                 → 成员退出
  • 权限：档案写操作（addBehavior/addGift/redeemGift/updateProfile/deleteProfile）允许家庭内所有成员（共同参与模型）；管理操作（移除成员/删除家庭）仅 Owner。全部走现有 JWT + PDO 预处理。
  • 并发：多成员同时记录同一孩子 → 积分 UPDATE 采用原子自增（现状已满足），前端乐观更新 + 进入页签时重拉（现有 updateUI 模式）。
  • 前端：设置/家庭入口（个人中心新增"家庭"区块）→ 家庭页：邀请码展示+复制、成员列表、退出/移除；登录响应增加 family 信息。
  • Freemium 预留：家庭共享永久免费，成员上限 5 人（含 Owner）；Pro = 增量价值（模板库/AI/高级导出/去水印海报），R2 直接启用。

5.1.3 验收清单（QA 可执行）

  1. Owner 创建家庭 → 拿到 6–8 位邀请码 → 复制成功。
  2. 新账号输入邀请码加入 → 登录后看到同一档案列表 → 记录一条行为 → Owner 刷新可见且积分一致。
  3. 成员兑换愿望 → Owner 侧兑换记录/积分同步。
  4. Owner 移除成员 → 该成员刷新后提示无权限（401/403 处理）。
  5. 旧账号迁移：注册于 8-08 前的用户升级后档案/行为/成就完整。
  6. 邀请码过期/撤销后无法加入。
  7. 并发：两人同时 +5，最终积分正确累加。

5.2 SEO 内容页 ×3（快赢）

目标："行为积分"是行内词、家长不这么搜。改用真实搜索词建立自然流量入口，并把用户引导到产品。目录 articles/，静态 HTML，双语（zh/en，hreflang 双向互指），主攻 Google/Bing（域名未备案）。

  • 选题（含「免费打印」进 title）：①《积分奖励表模板（可打印）50 个》②《儿童自律培养：积分制实操指南》③《儿童愿望清单 + 兑换表模板》。均内链到 behavior-templates.html 与首页。
  • 技术要求：语义化标签 + JSON-LD (Article + FAQPage + BreadcrumbList)（吃富摘要）+ 800 字以上原创正文 + 站内互链（关键词锚文本）+ 更新 sitemap.xml/robots.txt。
  • CTA「内容换注册」：文章给清单，打印版 / 愿望清单文件注册可得（转化预期 +2~3×）；每页至少 2 个站内 CTA。
  • 验收：页面可被 Google/Bing 收录（提交 Search Console + Bing Webmaster），GSC 可查「文章→注册」漏斗。

5.3 埋点（最小可用）

  • 事件：register / login / add_behavior / add_gift / redeem / poster_generated / invite_created / member_joined / calendar_view / profile_switch。
  • 实现：前端事件 → localStorage 队列批量上报 → 服务端 analytics_events（event, user_id, family_id, ts, extra JSON）按日聚合查询。
  • 验收：R1 结束时可查询"每日活跃家庭数 / 海报生成数 / 邀请转化数"。

5.4 海报带邀请链接（增长裂变）

目标：把已上线的「分享海报」变成获客入口——海报底部加家庭邀请链接 / 二维码（带家庭 invite 或可生成专属分享码），未注册用户扫码/打开即进入注册并自动带入邀请，注册后 Owner 侧出现新成员（与 5.1 邀请机制打通）。

  • 实现：海报 canvas 底部加一行邀请短链 / 二维码（指向 /register?inv=CODE 或由前端生成）；分享走 navigator.share 时附带链接。
  • 埋点：poster_generated 与落地页 invite_created / member_joined 串联看转化。
  • 验收：生成海报含可点击邀请链接；新用户经链接注册后归属对应家庭。

六、R2+ 预研项

  • Freemium 分层建议：家庭共享永久免费（5 成员） + 全部基础功能（多孩/成就/趋势/日历/海报/CSV）；Pro = 增量价值：模板库 / AI 建议 / 高级导出 / 去水印海报。定价：月 ¥9.9（锚点）｜年 ¥68 主推（首年 ¥38）｜终身 ¥98–128。
  • 支付：国内 → 微信支付 Native/H5 或支付宝（需商户号与域名资质）；海外 → Stripe。R2 排期需 商户资质进度确认（风险依赖，见第七节）。
  • AI 建议：接入 OpenAI 兼容接口，按次计费、仅 Pro 使用、输入输出做长度与敏感词约束；先灰度 10% 用户。
  • 模板社区：v1 只做"发布/浏览/收藏/使用"，审核用关键词过滤 + 举报，运营期人工抽审。

八、工程约定（延续）

  • 部署铁律：任何推送前必须本地检查通过（JS→node --check、PHP→php-parser、HTML→div 平衡），走 scripts/deploy-ftp.py（内置 preflight + 上传后线上字节校验）。线上用户优先，未经检查不上线。
